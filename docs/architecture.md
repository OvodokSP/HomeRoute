# Как устроен HomeRoute

Эта страница предназначена для тех, кому нужны технические детали. Для обычной установки начинать лучше со страницы [«С чего начать»](start.md).

## Общая схема

HomeRoute не создаёт собственный VPN-протокол. Он связывает несколько существующих компонентов в одну воспроизводимую систему.

Проверенный путь выбранного трафика выглядит так:

```text
домашнее устройство
→ HydraRoute Neo
→ набор адресов opkgtun0
→ служебная метка 0x3001
→ правило маршрутизации
→ таблица 301
→ интерфейс opkgtun0
→ AmneziaWG 2.x
→ VPS
→ AWG2
→ интернет
```

## За что отвечает каждый компонент

- **KeeneticOS и Entware** — среда, в которой работают дополнительные программы на роутере.
- **HydraRoute Neo** — выбирает, какой трафик отправить по отдельному маршруту.
- **`opkgtun0`** — интерфейс AmneziaWG на роутере.
- **метка `0x3001` и таблица `301`** — внутренний механизм, связывающий выбранный трафик с `opkgtun0`.
- **VPS и AWG2** — принимают туннель от домашнего роутера и выпускают выбранный трафик в интернет.
- **AdGuard Home** — обслуживает DNS для клиентов туннеля.
- **nfqws** — отдельный необязательный слой и не является частью основного AWG-маршрута.
- **tg-ws-proxy** — резервный вариант для Telegram.

## Почему используются фиксированные имена и номера

`opkgtun0`, `0x3001` и таблица `301` сохранены как часть проверенной конфигурации. Пока проект развивается, их нельзя молча менять: иначе диагностика, восстановление и инструкции перестанут описывать одну и ту же систему.

## Что больше не используется

Из эталонной конфигурации удалены старые элементы:

- `Wireguard0` и `nwg0`;
- старая политика `HydraRoute`;
- метка `0xffffaab`;
- таблица `4098`;
- старый WireGuard-peer Keenetic;
- правило `WG443_TEST`;
- дублирующий peer с тем же адресом клиента.

## Версия AmneziaWG

Проверенная версия HomeRoute использует AmneziaWG 2.x. Переход на 3.x будет отдельным обновлением только после появления совместимой и проверенной реализации для целевого KeeneticOS.
