# Аппаратные требования

HomeRoute использует evidence-first модель требований. Для первой воспроизводимой версии нам не требуется заранее находить физический минимум железа: рабочая текущая конфигурация принимается как **verified baseline / supported floor**.

## Статусы доказательности

### Verified baseline

Конфигурация фактически используется текущим HomeRoute Golden State и принимается как проверенная рабочая опорная точка.

### Expected compatible

Ресурсы устройства не ниже verified baseline, а программная среда и архитектура совместимы с обязательными компонентами HomeRoute. Такой статус означает обоснованное ожидание работоспособности, но не заменяет реальный clean reproduction на конкретной модели.

### Not validated

Хотя бы один существенный ресурс ниже verified baseline либо совместимость архитектуры/прошивки/Entware/AWG tooling ещё не подтверждена. `Not validated` **не означает `Not suitable`**: это только отсутствие доказательства.

### Not suitable

Несовместимость подтверждена воспроизводимым наблюдением: отсутствует необходимая программная среда, обязательный компонент не может быть запущен, не хватает ресурса при фактической установке либо существует иная подтверждённая блокировка.

## Supported floor: reference router

Текущий рабочий reference-router принимается как проверенная нижняя граница поддержки первой версии HomeRoute:

| Параметр | Verified baseline |
|---|---|
| Устройство | Netis N6 v1 AX1800 с KeeneticOS port |
| CPU | MediaTek MT7621AT / MIPS, класс 880 MHz |
| RAM | 256 MB |
| Flash | 128 MB NAND |
| Package environment | рабочий Entware/OPKG |
| HomeRoute runtime | фактически работающий Golden State |

Для первой версии HomeRoute устройство может считаться `Expected compatible`, если одновременно выполняются условия:

1. RAM **не меньше 256 MB**;
2. постоянное хранилище/flash **не меньше 128 MB** либо имеется отдельно подтверждённый объём Entware-хранилища, достаточный относительно reference-router;
3. CPU/архитектура поддерживает требуемые HomeRoute-компоненты; для другой архитектуры более высокая частота сама по себе не считается доказательством совместимости;
4. доступен рабочий KeeneticOS или проверяемый KeeneticOS port;
5. доступен Entware/OPKG;
6. для архитектуры доступны обязательные AWG2/HRNeo-side компоненты или существует воспроизводимый способ их установки.

Устройство с меньшим объёмом RAM/flash не объявляется несовместимым — оно получает `Not validated` до отдельной проверки.

## Recommended router profile

Для покупки нового оборудования можно использовать более консервативный профиль `Expected compatible / recommended`:

- 512 MB RAM или больше;
- 128 MB flash или больше, предпочтительно 256 MB;
- современный многоядерный CPU с поддерживаемой Entware-архитектурой;
- native Keenetic с официальным OPKG предпочтительнее ported-устройства, если остальные требования одинаковы.

Этот профиль даёт больший ресурсный запас, но до clean reproduction на конкретной модели остаётся `Expected`, а не `Verified`.

## Supported floor: reference VPS

Текущий VPS с работающим HomeRoute/AWG2/AdGuard принимается как verified baseline полного серверного контура:

| Параметр | Verified baseline |
|---|---|
| vCPU | 1 |
| RAM | около 1.9 GiB |
| Disk | 30 GB |
| OS | Ubuntu 26.04 LTS |
| Runtime | Docker + текущий AWG2/AdGuard stack |

Для первой версии VPS считается `Expected compatible`, если он предоставляет **не меньше 1 vCPU, 1.9 GiB RAM и 30 GB диска** и сохраняет совместимую Linux/Docker/AWG2 среду.

VPS ниже этой конфигурации остаётся `Not validated`. Это не противоречит меньшим upstream-минимумам отдельных компонентов: HomeRoute оценивает полный совместный стек, а не только возможность запуска одного AWG-сервиса.

## Что означает «лучше текущего»

Правило монотонности применяется только к количественным ресурсам при сохранении совместимой платформы:

- больше RAM — не хуже baseline;
- больше доступного storage — не хуже baseline;
- больше vCPU на VPS — не хуже baseline;
- более производительный CPU допустимо считать положительным фактором только после подтверждения совместимой архитектуры и наличия обязательных бинарников.

Нельзя автоматически считать совместимым устройство только потому, что у него выше частота CPU или больше flash, если отсутствует нужная программная среда.

## Практическая политика первой версии

Таким образом, для v1 применяем не поиск абсолютного физического минимума, а поддержку относительно доказанной точки:

- **ниже baseline** → `Not validated`;
- **равно baseline и это текущая фактически работающая конфигурация** → `Verified baseline`;
- **выше baseline + совместимая программная среда** → `Expected compatible`;
- **фактически воспроизведено на другой модели** → `Verified`;
- **фактически доказана несовместимость** → `Not suitable`.

Позднейшие тесты на более слабом железе могут понизить supported floor без изменения этой модели доказательности.

Матрица совместимости ведётся отдельно: [`compatibility-matrix.md`](compatibility-matrix.md).
