# Аппаратные требования

HomeRoute не требует от конечного пользователя самостоятельного benchmarking. Вместо этого оборудование будет относиться к одному из трёх понятных классов.

## Не подходит

Устройство не способно разместить или запустить обязательные компоненты HomeRoute либо для него отсутствует необходимая и проверенная программная среда.

Статус должен опираться на проверяемую причину: несовместимая архитектура, отсутствие рабочего KeeneticOS/Entware-контурa, недостаток ресурса, подтверждённый фактической установкой, или другая воспроизводимая блокировка.

## Достаточно

Обязательный набор HomeRoute фактически запускается и работает без предполагаемого существенного запаса по ресурсам.

Этот класс не означает, что устройство подходит для любых будущих функций или дополнительных компонентов.

## Рекомендуется

Обязательный набор работает, а измеренные ресурсы оставляют подтверждённый запас для обновлений, дополнительных правил и optional-компонентов.

## Числовые пороги

**Конкретные числовые пороги CPU, RAM и storage будут определены только после inventory эталонной системы и дальнейшей проверки на других устройствах.**

До получения этих данных запрещено выдавать предполагаемые значения за минимальные или рекомендуемые требования.

## Как будет формироваться рекомендация

1. Снять read-only inventory reference-router.
2. Отделить обязательные зависимости от случайно установленных пакетов.
3. Зафиксировать фактическое потребление и доступный запас там, где это можно измерить воспроизводимо.
4. Повторить проверку на дополнительных устройствах.
5. Только после этого публиковать числовые границы и модели с соответствующим уровнем доказательности.

Матрица совместимости ведётся отдельно: [`compatibility-matrix.md`](compatibility-matrix.md).
