# Источники пакетов роутера

Этот документ фиксирует только то, что подтверждено upstream-документацией и может быть использовано будущим установщиком без догадок.

## Зачем отдельный манифест

Установщик HomeRoute не должен незаметно выполнять удалённый скрипт вида `curl ... | sh` и считать это воспроизводимой установкой.

Для автоматического применения нам нужно заранее знать:

- какой файл feed будет изменён;
- какую строку туда нужно записать;
- для какой архитектуры она предназначена;
- что было в файле до изменения;
- как вернуть исходное состояние при откате.

Поэтому источники пакетов описаны в `config/router-feed-manifest.json`.

## AmneziaWG / Chur

Upstream Chur Keenetic публикует явные feed-адреса для трёх поддерживаемых Entware-архитектур:

- `aarch64-3.10`;
- `mips-3.4`;
- `mipsel-3.4`.

Эти строки можно детерминированно записать в отдельный opkg-конфиг, предварительно сохранив его старое состояние.

В текущем upstream-примере используется канал `latest`. Это означает, что адрес feed известен, но содержимое feed не закреплено на конкретной версии. Для стабильного установщика позднее может понадобиться отдельное решение о закреплении релиза.

Источник: <https://github.com/ward-sentry/chur-keenetic>.

## HydraRoute Neo

Текущая официальная инструкция HydraRoute Neo предлагает сначала выполнить удалённый `install-feed.sh`, а затем установить пакет `hrneo`.

HomeRoute **не переносит эту команду в live-установщик автоматически**. Пока точная строка feed не зафиксирована независимо и не покрыта резервным копированием/откатом, этот этап остаётся блокирующим для live `apply`.

Источник: <https://github.com/Ground-Zerro/HydraRoute/blob/main/Neo/README.md>.

## Что уже реализовано для Chur

`router/feed-config.sh` выдаёт точную строку Chur feed для:

- `aarch64-3.10`;
- `mips-3.4`;
- `mipsel-3.4`.

Router `sandbox-apply` требует явный `HOMEROUTE_ENTWARE_ARCH`, создаёт `opt/etc/opkg/chur.conf` внутри sandbox и включает этот файл в ту же транзакцию, что и остальное управляемое состояние.

CI проверяет:

- все три поддерживаемые архитектуры;
- отказ на неизвестной архитектуре;
- первое создание `chur.conf`;
- повторный запуск как `NO CHANGE`;
- восстановление предыдущего `chur.conf` при принудительном провале verify.

HydraRoute Neo feed при этом **не создаётся**: для него live gate остаётся закрытым.

## Что уже можно тестировать

В sandbox можно тестировать:

1. создание транзакции;
2. снимок существующего файла;
3. создание нового управляемого файла;
4. повторный запуск без изменений;
5. провал проверки;
6. автоматический откат;
7. сохранность посторонних файлов.

Это не разрешает реальные изменения `/opt/etc/opkg` до live backup/restore validation.
