# HomeRoute для новичка: полный маршрут действий

Эта инструкция рассчитана на человека, который умеет открыть программу для SSH и вставить команду, но не обязан понимать Linux, Docker, таблицы маршрутизации и устройство VPN.

Главное правило: **не переходите к следующему шагу, пока предыдущий не дал понятный результат**.

## Что сейчас можно сделать полностью

На текущем этапе HomeRoute умеет безопасно:

- проверить роутер;
- проверить VPS;
- показать план будущей установки;
- проверить уже работающую систему;
- подсказать, на каком этапе возникла проблема.

Полностью автоматическая установка на пустой роутер и пустой VPS пока не выпущена. Когда она будет подтверждена на чистом стенде, эта инструкция будет дополнена командами реальной установки.

---

# Часть 1. Подготовьте всё необходимое

Перед началом должны быть:

- роутер с KeeneticOS;
- Entware на роутере;
- доступ к роутеру по SSH;
- VPS под вашим управлением;
- доступ к VPS по SSH;
- интернет на компьютере, с которого вы выполняете команды.

Если у вас обычный Keenetic, перепрошивать его для HomeRoute не нужно.

Если у вас Netis, Xiaomi, Cudy или другой сторонний роутер, сначала нужен проверенный порт KeeneticOS именно для вашей модели.

## Что такое «окно роутера» и «окно VPS»

Удобнее открыть два отдельных окна PuTTY или другого SSH-клиента:

- первое окно — подключение к роутеру;
- второе окно — подключение к VPS.

Не вводите команды для VPS в окно роутера и наоборот.

---

# Часть 2. Зайдите в shell роутера

Подключитесь к роутеру по SSH.

На Keenetic вы можете увидеть приглашение вида:

```text
(config)>
```

В этом случае введите:

```text
exec sh
```

После этого должно появиться приглашение shell, например:

```text
/ #
```

Если вы уже сразу видите shell, ничего дополнительно вводить не нужно.

---

# Часть 3. Проверьте роутер

Вставьте блок целиком:

```sh
cd /tmp

wget -O homeroute-preflight-router.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/router/preflight-router.sh

chmod 700 homeroute-preflight-router.sh

sh ./homeroute-preflight-router.sh
```

## Что делает эта команда

Она **ничего не устанавливает и не меняет**.

Скрипт только смотрит:

- архитектуру процессора;
- объём памяти;
- свободное место;
- Entware;
- `opkg`;
- наличие компонентов HomeRoute.

## Что считать нормальным результатом

В выводе должны появиться сведения о системе и строки:

```text
HOMEROUTE_INVENTORY ...
```

Если скрипт завершился без сообщения об ошибке, снимок получен.

Если есть ошибка — не пытайтесь чинить систему наугад. Скопируйте ошибку и откройте [ЧаВо](faq.md).

---

# Часть 4. Посмотрите план установки роутера

Эта команда также ничего не меняет.

```sh
cd /tmp

wget -O homeroute-router-install.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/router/install.sh

chmod 700 homeroute-router-install.sh

sh ./homeroute-router-install.sh plan
```

Вы должны увидеть план и служебные строки `HOMEROUTE_PLAN`.

Если программа пишет, что режим `apply` заблокирован — **это нормально**. Реальная автоматическая установка пока специально отключена.

### Важно

Не пытайтесь заменить `plan` на `apply`. До завершения контрольного теста `apply` должен завершаться отказом.

---

# Часть 5. Подключитесь к VPS

Откройте второе SSH-окно и подключитесь к вашему VPS.

Обычно после входа вы увидите приглашение командной строки Linux, например:

```text
root@server:~#
```

Имя сервера может быть другим.

---

# Часть 6. Проверьте VPS

Вставьте:

```sh
cd /tmp

curl -fsSLo homeroute-preflight-vps.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/vps/preflight-vps.sh

chmod 700 homeroute-preflight-vps.sh

sh ./homeroute-preflight-vps.sh
```

Скрипт ничего не устанавливает.

Он проверяет:

- Linux;
- процессор;
- память;
- диск;
- Docker;
- наличие ожидаемых контейнеров, если они уже установлены.

В конце будут строки `HOMEROUTE_INVENTORY`.

Если Docker или контейнеров ещё нет, это не обязательно ошибка оборудования: это может означать только то, что сервер ещё не настроен.

---

# Часть 7. Посмотрите план установки VPS

```sh
cd /tmp

curl -fsSLo homeroute-vps-install.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/vps/install.sh

chmod 700 homeroute-vps-install.sh

sh ./homeroute-vps-install.sh plan
```

Команда показывает будущие действия и ничего не меняет.

Если `apply` указан как заблокированный — это ожидаемое состояние текущей версии.

---

# Часть 8. Если HomeRoute у вас уже работает

На уже настроенной системе можно выполнить полную диагностику.

## Проверка роутера

```sh
cd /tmp

wget -O homeroute-doctor-router.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/router/doctor-router.sh

chmod 700 homeroute-doctor-router.sh

sh ./homeroute-doctor-router.sh
```

Ищите итоговую строку:

```text
HOMEROUTE_DOCTOR ... result=PASS
```

Если `result=PASS` — обязательные проверки прошли.

Если `result=FAIL` — выше в выводе будет хотя бы одна строка `[FAIL]`. Именно её нужно разбирать первой.

## Проверка VPS

```sh
cd /tmp

curl -fsSLo homeroute-doctor-vps.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/vps/doctor-vps.sh

chmod 700 homeroute-doctor-vps.sh
```

Для полной проверки конкретного развёртывания скрипту могут потребоваться локальные параметры контейнеров и клиента. Эти данные относятся к конкретной установке и не публикуются в репозитории.

---

# Часть 9. Что делать после перезагрузки

Если HomeRoute уже настроен, после обычной перезагрузки роутера вручную восстанавливать маршруты не должно требоваться.

Если сервис перестал работать:

1. не переустанавливайте HomeRoute;
2. запустите `doctor-router.sh`;
3. найдите первый `FAIL`;
4. проверьте VPS с помощью `doctor-vps.sh`;
5. только после диагностики переходите к исправлению.

---

# Часть 10. Где сейчас нужно остановиться при установке с нуля

Если вы начинаете с совершенно чистого роутера и чистого VPS, текущая публичная версия HomeRoute пока заканчивается на этапах:

- проверка оборудования;
- сбор сведений;
- проверка совместимости;
- просмотр плана установки.

**Не нужно самостоятельно придумывать недостающие команды установки.**

Полная автоматическая установка будет открыта только после того, как проект подтвердит:

- резервное копирование;
- безопасный откат;
- установку на чистом стенде;
- работу после перезагрузки;
- повторный запуск без дублирования настроек.

---

# Краткая шпаргалка

Если вы запутались:

1. Определите, в каком вы окне: роутер или VPS.
2. Если только проверяете оборудование — запускайте `preflight`.
3. Если хотите увидеть будущую установку — запускайте `install.sh plan`.
4. Если система уже работает и нужно проверить её — запускайте `doctor`.
5. Не используйте `apply`, пока документация прямо не сообщит, что он разрешён.
6. При любой ошибке сохраните полный вывод и сначала прочитайте [ЧаВо](faq.md).
