# HomeRoute для новичка: полный маршрут действий

Эта инструкция рассчитана на человека, который умеет открыть программу и скопировать готовую команду, но не обязан разбираться в Linux, Docker, VPN и маршрутизации.

Главное правило: **не переходите к следующему шагу, пока предыдущий не дал понятный результат**.

## Сначала выберите свой сценарий

### Я хочу понять, подходит ли моё оборудование

Выполните только:

1. подключение к роутеру;
2. предварительную проверку роутера;
3. подключение к VPS;
4. предварительную проверку VPS.

После этого остановитесь. Устанавливать ничего не нужно.

### HomeRoute у меня уже работает, хочу проверить состояние

Перейдите сразу к разделу **«Диагностика уже работающей системы»**.

### Я хочу установить HomeRoute с нуля

Пройдите предварительную проверку роутера и VPS, затем откройте план установки.

На текущей публичной версии **остановитесь после режима `plan`**. Реальное автоматическое применение настроек пока специально заблокировано до контрольного теста на чистом стенде.

---

# Часть 1. Что подготовить

Нужны:

- роутер с KeeneticOS;
- Entware на роутере;
- доступ к роутеру по SSH;
- VPS под вашим управлением;
- доступ к VPS по SSH;
- компьютер с интернетом.

Если у вас обычный Keenetic, перепрошивать его для HomeRoute не нужно.

Если у вас Netis, Xiaomi, Cudy или другой сторонний роутер, сначала нужен проверенный порт KeeneticOS именно для вашей модели.

## Что заранее запишите для себя

Не публикуйте эти данные в GitHub:

- адрес роутера в домашней сети;
- имя пользователя роутера;
- пароль роутера;
- адрес VPS;
- имя пользователя VPS;
- пароль или другой способ входа на VPS.

HomeRoute не требует добавлять эти данные в публичный репозиторий.

---

# Часть 2. Как подключиться через PuTTY

Если вы используете другой SSH-клиент, смысл тот же.

## Окно №1 — роутер

1. Запустите PuTTY.
2. В поле **Host Name (or IP address)** введите адрес вашего роутера.
3. **Port**: обычно `22`, если вы сами его не меняли.
4. **Connection type**: `SSH`.
5. Нажмите **Open**.
6. При первом подключении PuTTY может показать предупреждение о ключе сервера. Убедитесь, что подключаетесь именно к своему роутеру, и только после этого подтвердите подключение.
7. Введите имя пользователя и пароль роутера.

При вводе пароля символы могут **вообще не отображаться**. Это нормально для SSH.

После входа Keenetic может показать:

```text
(config)>
```

Введите:

```text
exec sh
```

После этого должно появиться приглашение примерно:

```text
/ #
```

Это и есть окно, куда вводятся команды для роутера.

## Окно №2 — VPS

Откройте ещё одно окно PuTTY.

1. В **Host Name** введите адрес VPS, который выдал хостинг-провайдер.
2. Оставьте SSH-порт, указанный провайдером; если он не менялся — обычно `22`.
3. Нажмите **Open**.
4. Введите пользователя, которого указал провайдер. На некоторых VPS это `root`, но не всегда.
5. Введите пароль или используйте настроенный ключ.

После входа приглашение может выглядеть так:

```text
root@server:~#
```

Имя сервера будет другим — это нормально.

## Как не перепутать окна

- приглашение `/ #` после `exec sh` — обычно **роутер**;
- приглашение вроде `root@server:~#` — **VPS**.

Не вставляйте команды для VPS в окно роутера и наоборот.

# Часть 3. Предварительная проверка роутера

В окне роутера вставьте блок целиком:

```sh
cd /tmp

wget -O homeroute-preflight-router.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/router/preflight-router.sh

chmod 700 homeroute-preflight-router.sh

sh ./homeroute-preflight-router.sh
```

## Что делает эта команда

Она **ничего не устанавливает и не меняет**.

Скрипт только проверяет:

- архитектуру процессора;
- объём памяти;
- свободное место;
- Entware;
- `opkg`;
- наличие компонентов HomeRoute.

## Что считать нормальным результатом

В выводе появятся сведения о системе и строки:

```text
HOMEROUTE_INVENTORY ...
```

Когда команда закончится, снова появится приглашение командной строки.

Если есть ошибка — не пытайтесь чинить систему наугад. Сохраните полный вывод и откройте [ЧаВо](faq.md).

# Часть 4. Просмотр плана установки роутера

Если вы только проверяете оборудование — этот шаг можно пропустить.

Если хотите увидеть, что будущий установщик собирается делать:

```sh
cd /tmp

wget -O homeroute-router-install.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/router/install.sh

chmod 700 homeroute-router-install.sh

sh ./homeroute-router-install.sh plan
```

Команда ничего не меняет.

Вы должны увидеть план и служебные строки `HOMEROUTE_PLAN`.

Если программа пишет, что `apply` заблокирован — **это нормальное состояние текущей версии**.

Не заменяйте `plan` на `apply` самостоятельно.

---

# Часть 5. Предварительная проверка VPS

Перейдите во второе окно — VPS.

Вставьте:

```sh
cd /tmp

curl -fsSLo homeroute-preflight-vps.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/vps/preflight-vps.sh

chmod 700 homeroute-preflight-vps.sh

sh ./homeroute-preflight-vps.sh
```

Скрипт ничего не устанавливает.

Он показывает:

- Linux и версию ядра;
- архитектуру;
- число vCPU;
- память;
- диск;
- Docker;
- состояние ожидаемых контейнеров, если они уже существуют.

В выводе будут строки:

```text
HOMEROUTE_INVENTORY ...
```

Если Docker или контейнеров ещё нет, это не обязательно означает проблему с VPS: сервер может быть просто ещё не настроен.

# Часть 7. Диагностика уже работающей системы

Если HomeRoute уже настроен, переустанавливать его не нужно.

## Проверка роутера

В окне роутера:

```sh
cd /tmp

wget -O homeroute-doctor-router.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/router/doctor-router.sh

chmod 700 homeroute-doctor-router.sh

sh ./homeroute-doctor-router.sh
```

В конце ищите:

```text
HOMEROUTE_DOCTOR ... result=PASS
```

- `PASS` — обязательные проверки прошли.
- `FAIL` — выше есть хотя бы одна строка `[FAIL]`; начинать нужно с неё.
- `WARN` — есть замечание, но это не всегда означает поломку.

## Проверка VPS

В окне VPS:

```sh
cd /tmp

curl -fsSLo homeroute-doctor-vps.sh \
  https://raw.githubusercontent.com/OvodokSP/HomeRoute/main/vps/doctor-vps.sh

chmod 700 homeroute-doctor-vps.sh
```

Для полной проверки конкретной установки могут понадобиться локальные параметры контейнеров и клиента. Их не нужно публиковать в открытом репозитории.

---

# Часть 8. Что делать после перезагрузки

Если HomeRoute уже настроен, после обычной перезагрузки вручную восстанавливать маршруты не должно требоваться.

Если нужный сервис перестал работать:

1. ничего не удаляйте;
2. не переустанавливайте пакеты;
3. запустите диагностику роутера;
4. найдите первый `FAIL`;
5. проверьте VPS;
6. только после этого переходите к исправлению.

---

# Часть 9. Где остановиться при установке с нуля

Если вы начинаете с чистого роутера и чистого VPS, текущая публичная версия пока заканчивается на:

- предварительной проверке;
- проверке совместимости;
- просмотре плана установки.

**Не придумывайте недостающие команды самостоятельно.**

Реальная автоматическая установка будет открыта после подтверждения:

- резервного копирования;
- безопасного отката;
- установки на чистом стенде;
- работы после перезагрузки;
- повторного запуска без дублирования настроек.

# Короткая шпаргалка

| Я хочу… | Что запускать |
|---|---|
| Проверить, подходит ли роутер/VPS | предварительную проверку (`preflight`) |
| Посмотреть, что будет делать установщик | `install.sh plan` |
| Проверить уже работающий HomeRoute | диагностику (`doctor`) |
| Реально установить всё автоматически | пока остановиться: `apply` ещё заблокирован |

Если вы запутались:

1. Посмотрите приглашение командной строки и определите, роутер это или VPS.
2. Не вводите команды `apply`.
3. Не удаляйте правила и файлы вручную.
4. Сохраните полный вывод команды.
5. Найдите похожую ситуацию в [ЧаВо](faq.md).
