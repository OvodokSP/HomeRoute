# Резервное копирование и откат

Статус: **транзакционный файловый механизм реализован и тестируется только в sandbox**. Это ещё не разрешает резервное копирование или откат на реальном Keenetic/VPS.

## Цель

Будущий изменяющий установщик должен уметь вернуть только объекты своей транзакции в состояние до применения изменений.

Откат не должен быть «сбросом системы» и не должен трогать посторонние файлы и настройки.

## Что уже реализовано

В репозитории есть `scripts/installer/file-transaction.sh`.

Он умеет:

- создавать отдельную транзакцию;
- фиксировать, существовал ли управляемый файл до изменений;
- сохранять исходный файл;
- создавать новый управляемый файл;
- не переписывать совпадающее состояние;
- проверять результат;
- откатывать изменения при ошибке;
- удалять только файл, созданный текущей транзакцией;
- оставлять посторонние файлы без изменений.

Механизм работает только внутри каталога с явным маркером `.homeroute-sandbox`. Он отказывается работать с системными корнями вроде `/`, `/etc`, `/opt`, `/root`, `/usr` и `/var`.

## Что проверяет CI

`tests/installer-sandbox-transaction.sh` выполняет для роутера и VPS:

1. первое применение;
2. проверку созданного состояния;
3. повторное применение и ожидание `NO CHANGE`;
4. принудительный провал проверки;
5. автоматический откат;
6. восстановление исходного файла;
7. сохранность постороннего файла;
8. отказ при отсутствии sandbox-маркера.

## Модель транзакции

Перед первым изменением управляемого файла манифест фиксирует одно из состояний:

- `present` — файл существовал, исходная версия сохранена;
- `absent` — файла не было, откат имеет право удалить только файл, созданный этой транзакцией.

Объект, которого нет в манифесте, откат не трогает.

## Почему live-режим всё ещё закрыт

Sandbox доказывает файловую модель транзакции, но реальная установка затрагивает больше типов объектов:

- opkg feed-файлы и пакеты;
- init-скрипты и hooks;
- маршруты и правила netfilter;
- интерфейс AmneziaWG;
- контейнеры Docker;
- DNS/NAT на VPS.

Для них ещё нужна отдельная live-safe реализация и контрольная проверка.

## Условие открытия live-apply

Live-режим можно рассматривать только после:

1. точного описания всех изменяемых объектов;
2. резервного копирования каждого существующего объекта;
3. проверяемого отката;
4. live backup/restore validation;
5. первого чистого воспроизведения.
